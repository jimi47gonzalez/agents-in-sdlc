最初は、プロジェクトに小さな機能を追加しました。より大規模な変更には、さらに堅牢なプロセスが必要です。GitHub Copilot app は組織の既存のフローに沿って作業できるように設計されており、適切なものを適切な方法で構築できます。このレッスンから数回にわたり、一般的なエージェント主導の開発プロセスを実践します。issue を使って新機能を開始し、コードが有効で、機能が期待どおりに動作することを確認し、最終的にプロジェクトへマージします。

> [!NOTE]
> 機能のワークフローを進める間は、同じセッションを使用します。通常は作業するファイルの種類ごとに異なるセッションや PR を使用しますが、ここでは中心となる概念に集中できるように手順を簡略化します。

このレッスンでは、次の内容を学習します。

- GitHub issue から新しいエージェントセッションを開始します。
- **Plan** モードで要件を定義します。
- **Autopilot** モードで新機能を実装します。
- コードをレビューします。
- ブラウザーキャンバスで機能を手動で検証します。

機能の作業を続けながら、リポジトリの instructions を更新し、既存の `quality-checks` skill をカスタマイズし、MCP による検証を追加して QA エージェントを作成し、機能の PR を作成します。

## シナリオ

Tailspin Toys のカタログが増え、訪問者がゲームをカテゴリや発行元で絞り込めるようにしたいと考えています。バックログの issue には機能の概要がありますが、カテゴリを組み合わせる方法など、コーディング前に合意が必要な詳細もあります。Plan モードで決定事項を整理し、範囲を明確にしてから Autopilot に実装を依頼します。

## 背景

AI コーディングエージェントを開発フローに導入しても、基本は変わりません。むしろ、基本はさらに重要になります。多くの開発者は、次のような流れで作業します。

1. 必要な作業の詳細が記載された issue を開きます。
2. 構築する内容の計画を作成します。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションプロセスが成功したら、コードをマージします。

> [!NOTE]
> 正確な手順はチームや組織によって異なりますが、多くの場合は上記の流れを変形したものです。

この標準的なアプローチを守ることで、AI が生成したコードが要件を満たし、人間が作成したコードと同じレビューと検証を受けるようにできます。

## セッションモード

**セッションモード**は、エージェントの自律性を制御します。プロンプトフィールドの下にあるドロップダウンから設定し、いつでも変更できます。

- **Interactive**: ユーザーとエージェントが共同で作業します。エージェントは変更を提案し、続行前に入力を待ちます。
- **Plan**: エージェントが計画を作成します。計画を実行する前に内容をレビューして承認します。
- **Autopilot**: エージェントが自律的に作業し、入力を待たずにコードを書いてテストを実行し、反復します。

Plan モードで開始し、計画をレビューしてから、Autopilot で実装します。

## Issue からセッションを開始する

開始する前に、星評価の PR がマージされ、ローカルの `main` が最新であることを確認します。

1. サイドバーの **Sessions** で Tailspin Toys のリポジトリフォルダーを選択し、リポジトリの上部ナビゲーションで **Issues** を選択します。**Allow users to filter games by category and publisher** を開きます。これはテンプレートに含まれる既存の issue なので、新しく作成する必要はありません。
2. **New session** を選択し、更新済みの `main` に基づく **new working tree** を選びます。

    ![GitHub Copilot app の Issue ビューで、New session ボタンを矢印で示した画面](../../../_images/app-new-session-from-issue.png)

3. issue がセッションに添付されていることを確認し、モードセレクターで **Plan** を選択します。

> [!NOTE]
> Node.js または npm が見つからない場合は、エージェントに `node --version` と `npm --version` を実行させます。自分のターミナルでは動作するのにセッションでは動作しない場合は、アプリの PATH またはバージョンマネージャーの設定を確認し、アプリを完全に終了して再起動します。失敗した操作とチェックを再試行してください。エージェントが npm を見つけられないという理由だけで npm を再インストールしないでください。

## フィルター機能を計画する

計画を立てることで、Copilot がコードを書く前にアプローチをレビューできます。issue から開始したため、Copilot は機能の依頼をコンテキストとしてすでに把握しています。次の内容を送信します。

```plaintext
Build this feature.
```

Copilot の質問に回答し、計画を issue の受け入れ条件と照らし合わせます。カテゴリと発行元によるフィルター、アクセシブルなコントロール、データアクセスの変更、テストが含まれていることを確認します。複数のカテゴリをどう組み合わせるか、一致するゲームがない場合にどうするかなど、不明確な動作について話し合います。

計画には、プロジェクトの既存ツールを使った lint、ユニットテスト、E2E テスト、型チェックを含めます。フィルター機能の実装とテストに範囲を絞ります。品質ワークフローを完了してから PR を作成します。計画の修正は承認前に依頼し、後で検証できるよう issue の URL と合意した補足事項を控えておきます。

## Autopilot を明示的に承認する

計画に納得したら、**Approve and implement this plan** または使用中のバージョンで表示される同等のオプションを選択します。承認するとモードが自動的に切り替わるとは限らないため、現在のモードを確認してください。モード表示が **Autopilot** になっていることを確認します。

Copilot が実装を開始します。作成した計画に沿ってコードを生成し、テストを実行しながら作業を反復します。

> [!NOTE]
> 承認するとすぐに実装が始まる場合があるため、先に計画をレビューしてください。依存関係の不足やポートの競合が報告された場合は、チェック完了と判断する前にセットアップの問題を解決します。自分で起動したサーバーだけを停止してください。

## 実装をレビューして検証する

生成されたコードも、ほかのコードと同様にマージ前にレビューします。コードを確認し、サイトを起動して動作も確かめましょう。

1. **Changes** を開き、フィルター機能の実装とテストを確認します。
2. 複数カテゴリや発行元の組み合わせも含め、結果を issue と承認した補足事項に照らし合わせます。変更が既存のリポジトリ instructions に従っていることも確認します。
3. lint、ユニットテスト、E2E テスト、型チェックの出力を確認します。スキップされたチェックは成功ではありません。
4. 実装を承認する前に失敗を解消し、該当するチェックを再実行します。Playwright の E2E 設定はビルドしてプレビューを配信し、ローカルサーバーを再利用できます。以前のレッスンではなく、この worktree のサーバーがテストに使われていることを確認してください。

## 新機能を試す

コードに問題がないように見えても、実際に動くでしょうか。前と同じようにアプリを起動し、ブラウザーキャンバスでサイトを開きます。

1. 次のプロンプトを使い、アプリを起動してブラウザーキャンバスで開くよう Copilot に依頼します。

   ```plaintext
   Start the app and open it in the browser canvas.
   ```

2. しばらくするとアプリが起動し、Copilot app 内にブラウザーウィンドウが開きます。
3. カテゴリを選択し、結果がそのカテゴリに一致することを確認します。フィルターを解除してから発行元を選択し、結果がその発行元に一致することを確認します。
4. カテゴリと発行元のフィルターを組み合わせ、issue と承認した計画に合う結果になることを確認します。複数カテゴリがサポートされている場合は、合意した組み合わせの動作を確認します。
5. 該当するゲームがない組み合わせを試し、空の状態を確認します。フィルターを解除またはリセットして、一覧全体が戻ることを確認します。
6. 確認が終わったら、次のプロンプトを使い、このセッションで起動した開発サーバーを停止するよう Copilot に依頼します。

   ```plaintext
   Stop the dev server and close the browser canvas.
   ```

## 次のレッスンのためにセッションを維持する

フィルター機能の PR は、まだ作成またはマージしないでください。レッスン 4 から 8 まで、同じセッション、worktree、ブランチを維持します。次のレッスンでは、フィルター機能にカスタム instructions を適用し、skill と QA の改善を追加してから、レッスン 8 で変更をまとめて PR を作成、マージします。開発サーバーを停止した後、セッションをそのままにして、次のレッスンで再開してください。
